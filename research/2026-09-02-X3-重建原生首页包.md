## 源怎么同步到本车道 HEAD

`/tmp/kuca-x2` 还在，但不能 `git fetch` / `checkout`：它的 `.git` 是文件，指向已不存在的 X2 worktree（`gitdir: <主仓>/.git/worktrees/20260902-145708-X2-…`），`git -C /tmp/kuca-x2 rev-parse HEAD` 直接 fatal。

用的方法：**rsync 源目录**（不是 git fetch）。

同步前 clone 里 Home 仍是 S1：`screen: PhoneWebRouteScreen`。

```
rsync -a --exclude node_modules --exclude ios --exclude build --exclude .expo \
  <本车道>/apps/ /tmp/kuca-x2/apps/
rsync -a --exclude node_modules <本车道>/packages/ /tmp/kuca-x2/packages/
rsync -a <本车道>/scripts/ /tmp/kuca-x2/scripts/
cp package.json pnpm-lock.yaml pnpm-workspace.yaml t3.json tsconfig.base.json /tmp/kuca-x2/
```

没有 `--delete`，`apps/mobile/ios`、Pods、`node_modules` 原样留着。

同步后 `cmp`：`Stack.tsx`、`PhoneWebRouteScreen.tsx`、`SettingsRouteScreen.tsx`、`ThreadFeed.tsx`、`pnpm-lock.yaml` 与本车道 HEAD 逐字节相同。Home 已是 `screen: HomeRouteScreen`。

第一次曾用 `git ls-files | rsync --files-from`，macOS rsync 把 `research/` 里中文文件名拆坏（`stat: No such file`）。改目录 rsync 后一次过。构建不依赖那些 research 文件。

未跑 `pnpm install`：lock 没变，clone 里 `expo-sqlite@56.0.5` 还在。未跑 `pod install`：`Pods.xcodeproj` 已含 `CCACHE_BINARY`。未 `xcodebuild clean`。

## 命令原文

PATH 包装（X2 / R5 同一招），只给 argv 追加 `-allowProvisioningUpdates`：

```
# /tmp/kuca-x3-bin/xcodebuild
real=/Applications/Xcode.app/Contents/Developer/usr/bin/xcodebuild
exec "$real" "$@" -allowProvisioningUpdates   # 已有该 flag 则不再加
```

```
cd /tmp/kuca-x2
PATH="/tmp/kuca-x3-bin:$HOME/.bun/bin:/opt/homebrew/opt/node@24/bin:/opt/homebrew/bin:$PATH"
ELECTRON_SKIP_BINARY_DOWNLOAD=1 USE_CCACHE=1 \
  ./scripts/build-ios-release.sh --expect-js 'phone.kuca.app'
```

脚本只收一个 `--expect-js`。构建时探 `phone.kuca.app`；编完再跑一次 `--verify-app` 探 `HomeRouteScreen`。两条都过。

脚本打印的 argv：

```

```

实际 invocation（wrapper 加上了 flag）：

