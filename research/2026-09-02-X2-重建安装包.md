## 命令原文

工作副本里 `apps/mobile/ios` 被 gitignore，HEAD 里没有。从主树只读拷来原生工程（不含 Pods，避开 S1 那种 Pods 指着主镜像路径）：

```
rsync -a --exclude Pods --exclude build --exclude xcuserdata \
  <主树>/apps/mobile/ios/ apps/mobile/ios/
```

JS 依赖：

```
pnpm install --frozen-lockfile
# 第一次卡在 electron postinstall 下 GitHub zip；杀掉后：
ELECTRON_SKIP_BINARY_DOWNLOAD=1 pnpm install --frozen-lockfile
```

第二次 1m 19.5s，`PNPM_INSTALL_OK`。`apps/mobile/node_modules/expo-sqlite` = **56.0.5**，与 `Podfile.lock` 的 `ExpoSQLite (56.0.5)` 一致。lock 路径存在于本副本 `node_modules/.pnpm/expo-sqlite@56.0.5_...`。

`.xcode.env.local`：

```
./scripts/kuca-mobile-ios-env.sh
# NODE_BINARY=<homebrew node@24>
# ENTERPRISE_REPOSITORY=https://maven.aliyun.com/repository/public
```

在本工作副本 ios 目录：

```
cd apps/mobile/ios
pod deintegrate
USE_CCACHE=1 ENTERPRISE_REPOSITORY=https://maven.aliyun.com/repository/public pod install
```

`pod deintegrate` 成功。`pod install` **失败**（见下）。RN Core 两个 tar 其实已经下完（debug 91.3M、release 28.8M）。

根因：车道目录名含中文。Ruby 4.0.6 `URI::File.build(path:)` 拒绝非 ASCII 路径组件。复现：

```
ascii: file:///tmp/kuca-x2/.../reactnative-core-0.85.3-debug.tar.gz   # OK
cn FAIL: URI::InvalidComponentError: bad component(expected absolute path component): .../X2-重新构建并签好-Kuca-iOS-安装包-1/.../reactnative-core-0.85.3-debug.tar.gz
```

处理：APFS clonefile 整份工作副本到 ASCII 路径（不改产品代码）：

```
cp -cR <本车道工作副本> /tmp/kuca-x2
cd /tmp/kuca-x2/apps/mobile/ios
USE_CCACHE=1 ENTERPRISE_REPOSITORY=https://maven.aliyun.com/repository/public pod install
```

`POD_INSTALL_OK`，62s，141 pods。ExpoSQLite 解析到 `/tmp/kuca-x2/node_modules/.pnpm/expo-sqlite@56.0.5_...`。`Pods.xcodeproj` 含 `CCACHE_BINARY`。

签名按 R5：PATH 里包一层 `xcodebuild`，给 Kuca scheme 追加 `-allowProvisioningUpdates`。然后：

```
cd /tmp/kuca-x2
./scripts/build-ios-release.sh --expect-js 'phone.kuca.app'
```

## 每个报错与处理

1. **工作副本没有 `apps/mobile/ios`**  
   gitignore。从主树只读 rsync，排除 Pods。不是产品代码改动。

2. **`pnpm install` 卡在 electron 下 GitHub zip**（约 8.5M / ~150M，走 `release-assets.githubusercontent.com`）  
   iOS 构建用不到 Electron。杀掉后 `ELECTRON_SKIP_BINARY_DOWNLOAD=1` 重跑，完成。

3. **本工作副本 `pod install`：`URI::InvalidComponentError: bad component(expected absolute path component)`**  
   完整原文（截自失败跑）：

   ```
   [ReactNativeCore] Downloading ReactNativeCore-prebuilt debug tarball from https://maven.aliyun.com/repository/public/com/facebook/react/react-native-artifacts/0.85.3/react-native-artifacts-0.85.3-reactnative-core-debug.tar.gz ...
   100 91.3M
   [ReactNativeCore] Downloading ReactNativeCore-prebuilt release tarball ...
   100 28.8M
   [ReactNativeCore] Resolved stable ReactNativeCore-prebuilt version:
   [ReactNativeCore] Failed to download release tarball: bad component(expected absolute path component): .../X2-重新构建并签好-Kuca-iOS-安装包-1/apps/mobile/ios/Pods/ReactNativeCore-artifacts/reactnative-core-0.85.3-debug.tar.gz
   [!] The `React-Core-prebuilt` pod failed to validate due to 1 error:
       - ERROR | attributes: Missing required attribute `source`.
   ```

   tar 已在盘上。失败点是 `URI::File.build`。处理：clone 到 `/tmp/kuca-x2` 再 `pod install`，一次过。

4. **ExpoSQLite `exsqlite3_*`**  
   本轮完整构建没有再出现。版本锁一致 + 本副本（ASCII 路径）`pod install` + Maven 镜像下全了 RN Core。没有做 `xcodebuild clean` 第二次。
