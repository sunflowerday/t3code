## 逐条：原文、判定、改动

### homeListItems.test.ts（3 条）

**1. `limits large groups to the initial visible count with a show-more row`**

```
AssertionError: expected [ { type: 'thread', …(3) }, …(132) ] to have a length of 500 but got 133
```

判定：用例过时。fixture 建 133 条线程，按旧常数 6 应截到 6 条；新常数 500 下 133 全部可见、无 show-more 行，故期望 500 实得 133。产品行为（500 条以内全显）正是 fork 要的。

改动：fixture 提到 `HOME_INITIAL_VISIBLE_THREADS + 100`，继续覆盖「超过初始页大小时截断 + show-more 行」这个原意图；`hiddenCount` 改为字面 100。断言全部常数符号化，之后常数再调也不会 silent break。

**2. `reveals more threads per show-more step and offers show-less when exhausted`**

```
AssertionError: expected [ { type: 'thread', …(19) } ] to have a length of 510 but got 20
```

判定：用例过时。fixture 20 条 < 500，show-more 行根本不出现，一次「显示更多」后 20 条全显。

改动：fixture 提到 `HOME_INITIAL_VISIBLE_THREADS + 2 * HOME_SHOW_MORE_STEP`（520），两次 show-more 仍有意义：一次点击后可见 510、`hiddenCount: HOME_SHOW_MORE_STEP`、`canShowLess: true`；两次点击后 520 全显、`hiddenCount: 0`；show-less 复位断言（回到初始常数）不变。

**3. `keeps sticky indices aligned across multiple expanded groups`**

```
AssertionError: expected [ +0, 9 ] to deeply equal [ +0, 8 ]
```

判定：用例过时。alpha 8 条 < 500，无 show-more 行，beta 的 header 从 index 8 移到 9。索引算术本身没错，错的是「header + 6 threads + show-more = 8」这个旧常数假设。

改动：alpha 提到 `HOME_INITIAL_VISIBLE_THREADS + 1`，保住「截断组夹在两组中间时粘性 header 索引对齐」这一独有覆盖（show-more 行也占一个索引位）；期望改为 `[0, HOME_INITIAL_VISIBLE_THREADS + 2]` 并符号化取项。

### homeThreadList.test.ts（2 条）

**4. `default view shows only threads from the last 5 days`**

```
AssertionError: expected [ 'recent-1', 'recent-2', 'old' ] to deeply equal [ 'recent-1', 'recent-2' ]
```

判定：用例过时。窗口约 100 年后 15 天前的 "old" 也在窗口内，默认视图全显正是 fork 提交说明里写的意图（owner 线程少，要完整列表，不要 5 天窗口）。

改动：改名为 `default view keeps every thread under Kuca's widened recency window`；断言 `recentThreads` 与 `threads` 均为 3 条全量。

**5. `falls back to the most recent 3 threads when none are within 5 days`**

```
AssertionError: expected [ 'thread-4', 'thread-3', …(3) ] to deeply equal [ 'thread-4', 'thread-3', 'thread-2' ]
```

判定：用例过时。5 条线程全部落进约 100 年的窗口，上游的 3 条 fallback 在 fork 行为下不可达。

改动：改名为 `keeps the full history when every thread is older than upstream's 5-day window`；断言 5 条全量、顺序 newest-first。产品里的 `RECENT_THREAD_FALLBACK_COUNT` 保留不动（dead-but-harmless，属产品决策，不属本轮）。

同文件相邻的 `does not apply the recency window while searching` 仍绿、语义在新行为下依然成立，未动。
